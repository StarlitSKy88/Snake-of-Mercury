# Unified Autopilot 完整架构总结

> 基于 Anthropic Harness 设计最佳实践，一人公司场景优化

---

## 一、项目概述

### 核心目标

**「弥补产品不足、放大产品价值」，而非仅仅修复 bug**

实现从用户简短需求（1-4 句话）到完整可运行产品的全自动化闭环开发流程。

### 核心特性

- ✅ **Phase 0 默认开启**：每轮迭代先经过产品创新阶段
- ✅ **完全自动化**：无人值守，正常轮次不询问用户
- ✅ **闭环迭代**：Phase 0 → 1 → 2 → 3 → 0 自动循环
- ✅ **智能收敛**：连续 2 轮无价值提升自动暂停
- ✅ **真对抗机制**：5 Agent 团队协作 + 3 轮辩论
- ✅ **上下文保护**：Phase 边界重置，防止溢出

## 四、关键技术决策

### 4.1 为什么 5 Agent 并行？

```
参考 Anthropic 设计文章：
- 单一 Agent 容易"自我评估偏差"（给自己的作品打高分）
- 多 Agent 对抗能产生更高质量的洞察
- 每个 Agent 必须有独立立场，不能互相附和
```

### 4.2 为什么真对抗而非模拟对抗？

```
模拟对抗（coordinator 代对比）：
- 深度浅，只是静态比较
- 无法产生"被说服后修正观点"的动态

真对抗（TeamCreate + 3 轮辩论）：
- Round 1: 每个 Agent 质疑其他 4 个视角
- Round 2: 每个 Agent 回应针对自己的质疑
- Round 3: planner 整合，输出增强版需求
- 允许认错，允许被说服后修正观点
```

### 4.3 为什么三层质量把关？

```
第一层（qa-evaluator + vibcoding）：
- 功能测试 + 代码审查 + 安全检查
- 发现 Bug 和基础问题

第二层（bb-browser）：
- 真实用户场景测试
- 登录态复用、反爬绕过
- 发现体验卡点

第三层（独立质量监督官）：
- 完全中立，不参与创作/开发
- 一票否决权，不通过禁止进入交付
- 收敛触发权，判断迭代是否有价值
```

### 4.4 为什么上下文重置？

```
参考 Anthropic 设计文章：
- 模型存在"上下文焦虑"（接近上限时草率收尾）
- 上下文压缩不能解决焦虑问题
- Phase 边界重置是最佳实践

触发条件：
- 单次 Phase 执行时间 > 30 分钟
- 上下文窗口使用 > 60%
- Agent 出现焦虑信号
```

### 4.5 为什么需要 Pivot 机制？

```
参考 Anthropic 设计文章：
- 最好的创意往往来自彻底推翻重来
- Anthropic 实验中第 10 轮突然重构为 3D 空间体验

策略：
- 分数上升 → CONTINUE（继续优化当前方向）
- 分数停滞 → PIVOT_MINOR（调整策略）
- 分数下降 → PIVOT_MAJOR（彻底推翻重来）
```

## 七、与 Anthropic 官方设计的关键差异

| 维度 | Anthropic 官方 | Unified Autopilot |
|------|---------------|-------------------|
| **Phase 0** | 无（直接规划） | ✅ 产品创新阶段（5 Agent 并行 + 真对抗） |
| **Agent 数量** | 3（Planner/Generator/Evaluator） | 6（5 创新 + 1 质量监督） |
| **对抗机制** | 隐式（Generator vs Evaluator） | ✅ 显式（TeamCreate + 3 轮辩论） |
| **质量把关** | 单层（Evaluator） | ✅ 三层（测试 + 真实用户 + 独立裁决） |
| **商业视角** | 无 | ✅ 商业闭环操盘手 |
| **收敛逻辑** | 无限循环 | ✅ 智能收敛 + 自主挖掘 |
| **上下文管理** | 压缩 + 重置 | ✅ 重置优先 + 焦虑信号识别 |
| **Pivot 机制** | 描述但未显式实现 | ✅ 显式策略（CONTINUE/MINOR/MAJOR） |
| **评估器校准** | 文章提到但未实现 | ✅ 4 种偏差 + 检查清单 |

## 八、适用场景

### ✅ 推荐使用

- 一人公司 / 独立开发者
- 需要「产品创新」而不仅是「写代码」
- 希望自动发现产品不足并迭代
- 长周期项目需要无人值守运行

### ❌ 不推荐使用

- 只需要简单 bug 修复
- 需要人工审核每一步
- 没有可用的 Claude API 讞配
- 不信任 AI 自动执行操作

---

## 九、已知限制

1. **模型依赖**：需要支持 Agent Teams 的模型（Claude 系列或兼容中转）
2. **API 成本**：完整流程可能消耗 $50-200 / 项目
3. **执行时间**：完整项目可能需要 4-6 小时
4. **上下文限制**：超长项目可能需要多次上下文重置
5. **部署风险**：Phase 3 自动部署需要提前配置好环境
